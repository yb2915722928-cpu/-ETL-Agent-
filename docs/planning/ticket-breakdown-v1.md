# ETL-Agent 首版纵向实施票拆分

状态：用户已确认并于 2026-11-13 发布全部 28 张实施子票，35 条直接阻塞边已核对。来源为已发布的 [spec #1](https://github.com/yb2915722928-cpu/-ETL-Agent-/issues/1)，产品基线和 TS-01–TS-09 测试边界不变。V01–V28 是方案标识，不是 GitHub 票号；真实编号及依赖见[发布映射](ticket-map-v1.md)。全部子票关联 #1 并标记 ready-for-agent；本次未改写或关闭父规格，未开展业务实现。

## 拆分规则

- 每票完成一个可以独立演示或验证的行为，包含所需持久化、公开 API、最小中文页面和对应测试；UI 不集中拖到最后。每票的失败/等待/拒绝状态也必须在页面和 API 中体现。
- 当前无业务代码，无需先行重构。旧 T00–T13 保留为技术主题参考，本提案不按旧横向模块一对一发布。
- 环境健康检查、版本/驱动锁定及外部协议实测随首次引入该依赖的行为交付；无法取得真实条件则记录缺失条件，不填入 L2 通过。早期配置实验仅针对隔离合成数据，不是生产 ExecutionRun 或免审批执行入口。
- V09–V11 的故障 Engine 仅在隔离 L1 测试配置运行，同样走公开业务 API，不开放生产故障注入端点。V12 才首次启用真实引擎受管搬运，启用前必须已有预算监督和停止保障。
- 关键安全语义随首次行为交付：V09 已有未知状态闭锁，V12 实测未知提交与停止的安全结果；V15 首次 Swap 已覆盖交换后控制事务失败。后续恢复票增加核对恢复能力，不推迟安全条件。
- 关键 EvidenceEvent 随各票原子记录，敏感数据持续扫描；测试只断言外部业务结果及真实事务/协议，不绑定私有函数、节点数或组件内部实现。
- 列出的均为直接阻塞边；传递依赖不重复列出。发布票不等于执行票，当前阶段不开发业务代码。

## 已确认并发布的纵向切片

### V01：初始化、登录与隔离项目协作

**阻塞：** 无，可开始。

**交付：** 启动最小 Vue/FastAPI/PostgreSQL/Redis 运行包，管理员初始化独立角色账号，成员登录、查看所属项目并管理项目成员。

**验收：** 实际持久化账号/归属/角色；跨租户和项目 ID、禁用账号、撤销角色在 API 被拒绝；页面有真实登录与权限状态。记录运行健康条件，不能把客户端存在当作服务可用。先记录必要身份变更审计事实，后续所有新业务事件沿用统一证据契约。

### V02：审计事件导出与独立验签

**阻塞：** V01。

**交付：** 审计人员查看 V01 的真实操作历史，导出带序号、哈希链和 Ed25519 检查点的证据，通过独立离线入口验证。

**验收：** 验证正常导出、非法归属下载、篡改/删除/重排；对照独立保留的旧检查点检测尾截断。明示可信检查点与密钥保管边界；为后续事务提供可复用证据追加契约。

### V03：受管凭据及 MySQL/Doris 连接探查

**阻塞：** V02。

**交付：** Maker 在连接页登记 MySQL 源与 Doris 目标，以加密 SecretReference 保存新凭据，经受限 P3 工具出口测试连通、生成 MetadataProfile 并查看脱敏样本。

**验收：** 资源白名单、只读账号、Schema/类型/近似统计及采样预算有效；不存在任意 URL/SQL 工具；缺主密钥拒绝相关服务启动，凭据不出现在 API/日志/制品/证据中。此票只登记新凭据，不提供绕过双批的既有凭据轮转。

### V04：PostgreSQL 与 CSV 资产探查

**阻塞：** V03。

**交付：** 同一资产管理流程新增 PostgreSQL 与受管 CSV，展示真实结构、脱敏样本与明确的源读取失败。

**验收：** PostgreSQL 控制库与源权限隔离；CSV 文件按项目授权，不接受任意主机路径；坏格式、编码错误和访问失败不伪造 Profile，不静默丢行。尚未支持的其他连接器不可操作。

### V05：手工 EtlPlan 与确定性派生审查

**阻塞：** V03。

**交付：** Maker 为最小 MySQL→Doris 有界计划编辑资源、映射、质量与预算，在 Studio 查看同源 HOCON、DAG 和确定性门禁结果。

**验收：** HOCON/DAG 只读派生，非法语法、Schema/类型、越权引用和未支持操作被拒绝；模型尚未接入时明确为手工设计。后续票扩展新操作必须同步扩展编译和门禁，不提前显示为可执行。

### V06：冻结 PipelineVersion 与版本 Diff

**阻塞：** V05。

**交付：** Maker 冻结通过门禁的候选，查看不可变制品及不同版本的映射、Schema、HOCON、规则 Diff。

**验收：** SHA256 可重算、相同规范输入稳定；业务事实变化影响相应摘要，时间戳/无关统计不污染执行指纹；冻结后修改被拒绝并要求新版本。下载遵守归属及脱敏要求。

### V07：冻结 Preparation 与独立双人审批

**阻塞：** V06。

**交付：** Maker 准备一次操作，数据与安全 Checker 在独立槽位批准或拒绝，页面展示资源、影响、质量、预算、凭据/策略版本及恢复事实。

**验收：** Prepare 不产生外部变更；P0 拒绝、P1/P2 双批、P3 受限自动授权；24 小时有效、审批不续期；自批、同人双槽、过期/撤权/冻结事实漂移被拒绝。本票可查看批准结果，但尚不提供引擎执行能力。

### V08：单次 Commit 与原子授权接受

**阻塞：** V07。

**交付：** Operator 提交已批准准备单，页面获得唯一 ExecutionRun 及待调度状态，接受的 ManagedCommand 与 Outbox 可持久查询。

**验收：** Ed25519 Capability 绑定主体/工具/环境/资源/制品，五分钟单次消费；消费、Run、Command、Outbox、关键证据在真实 PostgreSQL 一次事务成败。并发/重放不重复，同键异请求冲突；重查当前资格、策略与指纹。本票不虚报引擎已启动。

### V09：异步受管命令与 L1 幂等执行

**阻塞：** V08。

**交付：** 真实 Outbox/Redis/Celery 驱动隔离 L1 Engine，运行中心展示状态与关联，模拟响应丢失及 Worker 中断。

**验收：** Worker 验签 ManagedCommand 而不再次消费 Capability；重复消息、确认丢失不新建 Run、不盲目提交；未知时禁止重提、发布和清理，持有同一物理目标隔离。队列超过五分钟不等于旧命令自动失效，仍检查当前命令资格。L1 明确标识，不能计为真实搬运。

### V10：监督契约、指标与预算闭锁

**阻塞：** V09。

**交付：** 运行中心按冻结口径显示累计行数、字节、时长、吞吐、放大比和拒绝率；L1 注入阈值、缺失或陈旧指标，监督器阻止不安全推进并请求停止。

**验收：** 默认 100000 行、256 MiB、600 秒、2 倍、20%、约两秒观测；比例判定 99/100 条边界与小样本最终判断正确，其他预算无样本豁免；零分母显示暂无数据；未知字节不按零，不把估算当实测。发布否决可持久查询，不只靠页面状态。

### V11：终止确认、撤权与发布前清理

**阻塞：** V10。

**交付：** Operator 发起受管停止，观察请求与终止确认，只有确认旧任务停止才允许清理未发布资源；排队或运行时撤权、绑定密钥故障也走安全终止。

**验收：** L1 验证取消超时、迟到指标、失联 Worker、租约过期和在途调用；未知时不释放目标、不提前清理、不切换未批准凭据扩权恢复。记录检测/停止请求/终止确认及最终观测、超调，不宣称零超调或取消即回滚。

### V12：真实 Zeta 受管搬运至 Doris 影子表

**阻塞：** V11。

**交付：** 具名角色通过现有页面与审批流程，将有界 MySQL 合成记录经真实 Celery/SeaTunnel 写入未发布 Doris ShadowTable，在运行中心查看真实指标与终态。

**验收：** 固定真实引擎/connector/驱动版本，先验证作业关联、必要字节来源、停止确认；将 L1 不变量接到真实适配器。响应丢失进入持久待核对，不盲重提；重复投递、缺指标、源读取失败及停止异常均安全闭锁。真实搬运开关仅在预算和停止保障具备后启用，不发布正式表。

### V13：真实引擎待核对恢复与旧写入隔离

**阻塞：** V12。

**交付：** Operator 对提交或停止结果不明的原作业执行 Reconciliation，恢复原 Run 事实，确认旧写入被隔离后才可接续或释放目标。

**验收：** 实测提交成功但响应丢失、没有 jobId、Worker 崩溃、取消超时、续约失败；匹配原作业而非再提交。无法可靠核对时保留未知状态和隔离，不以租约到期自动接管。

### V14：质量双分支、错误记录与对账报告

**阻塞：** V12。

**交付：** Maker 配置清洗与必需规则，真实 SeaTunnel 将有效记录写入 ShadowTable、拒绝记录分流为 ErrorRecord，运行中心显示脱敏诊断和 QualityReport。

**验收：** NULL、多个 ErrorCode、显式过滤、sink 失败与重试均有对照；一条拒绝只计一次，仅同判定阶段/记录单元去重后满足已判定=有效+拒绝，分别报告源读取与最终写入。双 sink 任一失败不具备发布资格，不假定跨 sink 事务。

### V15：完整全量结果的质量受控原子发布

**阻塞：** V13、V14。

**交付：** 达标的完整全量 ShadowTable 经独立发布门禁和 Doris 单表 Swap 上线，记录 PublishedSnapshot，保留交换后的旧正式表。

**验收：** 实测稳定表身份与 Schema 门禁，正式数据与预期完整结果比较；质量报告缺失/不合格、预算异常、空输入或目标竞争均不发布。首个发布即验证 Swap 成功但 PostgreSQL 未提交/响应丢失时持久待核对、禁止再次交换/下一 Run/危险清理，不宣称跨库原子。

### V16：交换故障核对与控制状态恢复

**阻塞：** V15。

**交付：** Operator 从待核对状态恢复单次发布，根据稳定对象身份补齐正确控制事实，安全推进或继续阻断。

**验收：** 覆盖交换前失败、交换已完成响应丢失、控制事务未完成、重启后重复核对；不误交换、不误删旧正式表、不释放仍有旧写入的目标；实际表、发布快照、运行状态最终一致。无法证明时显式保留未知。

### V17：订单水位增量与完整历史保留

**阻塞：** V16。

**交付：** 同一 Pipeline 支持更新时间加主键、有界重叠回看和主键合并，构建含历史的完整订单宽表，并在确认发布后推进 Watermark。

**验收：** 同时间戳、重跑、晚到边界及失败批次有预期表对照；不漏历史、不重复，失败/未知不推进水位；规范源/维度合并状态与快照可恢复，大规模合并不在控制面搬运。不承诺 CDC、物理删除传播或无限迟到。

### V18：当前维度变化刷新历史订单

**阻塞：** V17。

**交付：** 用户维度变化时刷新受影响历史订单，在版本、运行和发布报告中显示约定的当前维度结果。

**验收：** 无新增订单但维度变化、同批订单和用户变化、重复运行均比较实际完整表；保持同目标串行与水位规则。明确非历史 as-of 语义，保留可回退的对应规范维度状态。

### V19：双审批回退上一快照与增量状态

**阻塞：** V18。

**交付：** Operator 另行 Prepare/双批/Commit 后，恢复最近一次发布前完整快照、Watermark 及对应规范合并/维度状态。

**验收：** 七天保留边界，旧表缺失/被改/身份不明/仍有写入均拒绝；验证维度变化后的回退与再次重放结果。回退自身异常也按对象身份核对，不将发布前清理当回退，不沿用新水位。

### V20：双审批凭据轮转与绑定失效

**阻塞：** V12。

**交付：** Operator 经 P1 独立双批轮转已登记凭据，在连接和审批页看到新版本以及旧 Preparation 的失效事实。

**验收：** 未批准轮转和扩大资源范围被拒绝；排队/运行中的绑定密钥不可用或撤权触发既有安全停止，不偷偷替换版本继续；并发及故障不得误报轮转完成，导出和日志无明文。

### V21：可选 Vault Profile 的真实凭据闭环

**阻塞：** V20。

**交付：** 部署选择 Vault KV v2 时，现有连接登记、只读探查与受管轮转使用相同业务流程，明确显示凭据存储 Profile。

**验收：** 真实 Vault 读写、权限拒绝、版本变化和服务不可用；相关行为失效关闭，不退回明文或未经批准的新凭据。默认加密 Profile 可独立运行；报告区分已验证 Profile 与未执行条件。

### V22：真实模型需求澄清与 Checkpoint 恢复

**阻塞：** V06。

**交付：** Maker 从自然语言进入已有 Studio，真实模型生成受支持 EtlPlan，缺参中断提问，跨请求与重启后继续原工作流并冻结版本。

**验收：** ConversationState、WorkflowState、ExecutionRun 不混用；真实模型只收需求和筛选元数据，不收凭据/原始样本；恢复绑定项目和修订。真实调用失败显式报错，演示 Provider 须主动选择并单独标识。

### V23：有限自动修复与模型 Profile 切换

**阻塞：** V22。

**交付：** Maker 查看最多两次修复及每轮门禁结果，必要业务变化转入澄清；在受管模型配置之间切换。

**验收：** 超过两次停止自动修复；扩大资源/预算、删除规则等不能由模型自行决定；冻结内容变化须新版本。至少一个真实模型实际生成，第二配置验证切换并如实报告可调用条件，不静默用演示结果补齐。

### V24：Beat 每次触发独立待审批申请

**阻塞：** V09。

**交付：** Maker 配置调度，真实 Beat tick 生成本次独立 Preparation，审批控制台展示待办；重复 tick 不重复建申请。

**验收：** 每次运行独立批准，不能复用历史 Capability/ApprovalDecision；调度变化、过期/漂移/撤权按现有规则处理。未审批不投递执行命令，能够按触发身份追踪申请与运行。

### V25：PostgreSQL/CSV 真实搬运与解析失败闭锁

**阻塞：** V04、V14。

**交付：** 已有设计、冻结、双批和运行流程支持 PostgreSQL/CSV 到 Doris 的真实受管搬运，并在运行中心展示可对账质量结果与源解析诊断。

**验收：** 扩展对应编译/门禁并验证正常值、NULL、质量违规；坏引号/列数/编码及 JDBC 不完整读取整批失败、不静默 SKIP，保存受管源引用和脱敏定位。未形成可靠记录的坏输入不伪造逐行 ErrorRecord，不借新源绕过凭据/资源/预算约束。

### V26：真实模型生成 Benchmark 与逐例报告

**阻塞：** V04、V23。

**交付：** 安全 Checker 从 Benchmark 页触发固定版本、至少二十例生成评测，查看首次/最终成绩、语法与映射/语义的逐例预期和失败原因。

**验收：** 用例使用三类源的真实 Profile；最多两次修复后最终正确率至少 90%，真实模型与演示成绩分开，记录模型/配置/数据集版本和分母。此票评价生成正确性，实际搬运 L2 由运行票及最终验收另列，不以作业成功代替语义正确。

### V27：安全 Benchmark 与受控策略激活

**阻塞：** V19、V20、V24。

**交付：** 安全 Checker 执行安全用例集，查看 P0/P1 拦截、漏拦截/误拦截与证据，并将策略建议经受控验证形成适用版本。

**验收：** 双批/回退/轮转/调度等关键拒绝路径及合法对照可复现；确定性安全硬门槛 100%，报告分母及失败；策略变化使旧绑定重新检查，模型不能直接改策略/降级。L0/L1/L2 不混报，必要真实验证未执行不得显示通过。

### V28：六界面联合验收与可重复交付包

**阻塞：** V21、V25、V26、V27。

**交付：** 整合各票已交付页面和入口，完成跨角色中文演示、总览真实汇总、固定版本 Compose 初始化/健康检查/数据复位及运维说明。

**验收：** 约 1000 订单/100 用户，约 5% 异常正常发布、约 30% 异常超 20% 中断清理，另行双批发布后回退及回退后重放；实际数据、指标和签名证据关联 AC-01–AC-09。各前序票应已有独立验收，本票负责跨票集成、六类页面一致性和复跑，不首次建设整套前端或补完基础功能。报告真实资源/版本/耗时，缺模型或 Docker 条件明确未执行。
