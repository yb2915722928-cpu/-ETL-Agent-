## 1. 首版范围与交付物

### 1.1 范围

| 能力 | 首版必须交付 | 后续范围或明确限制 |
| --- | --- | --- |
| 数据源与目标 | MySQL、PostgreSQL 数据库源，CSV 文件源，Doris 目标端；受管连接、连通性测试、MetadataProfile、字段类型、近似统计、脱敏样本 | Oracle、ClickHouse、Excel、JSON、Parquet、S3/MinIO、REST API 等其余连接器后续交付；未实现项不得展示为可用 |
| 数据处理 | 有界全量批处理、更新时间与主键水位增量、当前用户维度宽表、QualityContract、完整 ShadowTable 发布 | 不承诺持续 CDC、源端物理删除传播、跨源表事务快照、任意久远迟到修改捕获 |
| 智能生成 | 真实模型、澄清、LangGraph 中断恢复、结构化 EtlPlan、确定性 HOCON 渲染与门禁、最多两次自动修复 | 首版不直接编辑 HOCON，不做任意拖拽 DAG，不允许模型自行放宽质量和安全约束 |
| 执行治理 | 身份与项目隔离、双审批、Capability、事务 Outbox、Celery、SeaTunnel Zeta、运行监督、受管清理及最近一次发布回退 | 不承诺跨数据库与引擎事务、消息只投递一次、跨 sink 原子性或绝对零超调 |
| 运维与评测 | Compose 初始化、中文控制台与文档、真实演示、证据导出校验、L0/L1/L2 Benchmark | 不承诺企业级吞吐、高可用、灾备 SLO、每租户专属数据库或引擎集群 |

### 1.2 运行交付包

标准验收入口为 Linux 容器 Docker Compose 环境。交付 Vue 控制台、FastAPI、LangGraph 持久化存储、Celery Worker/Beat、PostgreSQL、Redis、SeaTunnel Zeta、MySQL、Doris 及合成业务数据。PostgreSQL 的控制面存储与源端测试数据须在权限和逻辑命名上区分。Vault KV v2 作为可选配置提供。

必须提供初始化、启动、健康检查、数据复位、演示、测试及结果导出的说明和入口。初始化应创建租户、项目、独立角色账号、合成数据与示例 Pipeline；初始化凭据不得写入版本化制品或日志。依赖、镜像、驱动和连接器采用经实际兼容性验证的固定版本，并记录配置及运行条件；本规格不预先指定尚未验证的 SeaTunnel 或 Doris 部署版本。

没有企业业务库不阻断验收，本地真实数据库及合成数据可作为数据环境。无真实模型密钥时可以运行确定性演示，但自然语言生成验收仍未完成。当前 Docker 客户端存在不等于 Docker 服务可用；服务连通、镜像拉取、资源容量和真实链路均待运行验证。

## 2. 用户身份、隔离与信任边界

平台使用本地账号、密码哈希及项目成员角色授权；首版不要求企业 SSO。服务端强制校验 Tenant、Project 与资源归属，不能依赖前端按钮隐藏。共享数据库与服务通过租户、项目范围实现隔离，覆盖 Connection、MetadataProfile、ConversationState、WorkflowState、Checkpoint、PipelineVersion、Preparation、ExecutionRun、日志、文件与制品下载。后台命令同样携带并校验归属。

| 身份 | 职责与限制 |
| --- | --- |
| Maker | 登记连接、受管探查、输入需求、编辑 Candidate、生成与调试、冻结版本、提交 Preparation；禁止审批自己的申请 |
| 数据 Checker | 审查需求、映射、Schema、脱敏结构、DAG 与质量规则，填写独立数据 ApprovalSlot |
| 安全 Checker | 审查资源、敏感分级、预算、SecretReference、回滚方案，填写独立安全 ApprovalSlot；管理安全策略和 Benchmark |
| Operator | 满足授权条件后 Commit，监控运行，发起受管取消、清理、回退及凭据轮转；验收使用独立账号 |
| 审计人员 | 按授权读取历史、审计、QualityReport、证据与 EvaluationReport，不获得执行或审批权限 |

同一申请的两个审批槽不能由同一自然人账号承担；同一人注册多个账号的身份核实属于平台外管理责任。角色标签不能替代具名 ApprovalDecision，账号撤权或禁用后不能继续依赖旧批准执行。

模型输出、提示词、源端元数据与样本、项目成员输入及任务消息均按不可信输入处理。平台基础设施管理员、执行环境与密钥托管处于受信边界；首版不声称能抵御同时控制数据库、签名密钥与验证程序的管理员。

## 4. 控制面、模型与三层状态

FastAPI、LangGraph、Celery、PostgreSQL 负责设计与治理，SeaTunnel 搬运业务数据；控制面不承接海量业务数据中转。小规模受管脱敏探查、合成数据初始化与错误摘要不是无限制数据导出通道。

分别持久化以下状态并通过显式关联标识连接：

- ConversationState：自然语言对话历史。
- WorkflowState：意图解析、澄清、生成、门禁、有限修复及受管试运行的 LangGraph 进度与 Checkpoint。
- ExecutionRun：独立批准的运行、引擎作业标识、指标、QualityReport、发布与恢复事实。

工作流至少覆盖需求解析、受管元数据读取、EtlPlan 生成、确定性渲染、语法与 Schema 门禁、有限修复、必要的独立受管试运行和准备审批。缺失业务信息时中断，补充后从持久化 Checkpoint 恢复；不能通过重建对话伪装为恢复原状态。

首版真实模型采用 OpenAI 兼容端点，支持模型 Profile、端点、模型名、超时及有限重试。模型凭据通过 SecretProvider 管理；真实调用失败时显式报错，切换演示 Provider 必须由用户主动选择并留下标识。真实模型至少参与需求解析或计划生成，EvaluationReport 记录服务与模型标识。确定性 Provider 的结果不得计入真实模型准确率。发送外部模型的内容仅限需求及经过筛选的元数据，禁止发送明文凭据和原始行样本。

EtlPlan 为唯一可编辑执行定义，HOCON 和 DAG 由其确定性生成。门禁覆盖语法、Schema/类型对齐、连接与 SecretReference、允许工具和资源范围、质量规则、预算及发布恢复约束。允许的自动修复最多两次；修复后重跑全部相关门禁。业务含义不明、扩大资源范围、增加预算、降低质量阈值或删除敏感保护必须澄清。通过门禁后冻结 PipelineVersion，计算制品 SHA256；版本不可原地修改，任何修复生成新版本。

## 5. 策略、准备、审批与提交

### 5.1 风险及工具入口

| RiskLevel | 含义及首版要求 |
| --- | --- |
| P0 | 最高风险、禁止；包括跨租户访问、明文凭据外传、未登记工具等，拒绝原因可解释且审计 |
| P1 | 正式发布、发布后回退、凭据轮转等高风险操作；独立数据和安全双审批 |
| P2 | 隔离范围的受限写入、试运行等；同样双审批，范围及预算较小 |
| P3 | 受限只读探查等；权限、白名单、范围与预算检查后可自动授权 |

PDP 根据 ToolIntent、资源、环境与数据分类确定风险和职责槽；模型只能提供分析，不能降级或豁免。连通性、元数据、样本读取和试运行都是受管工具操作。只读探查不等于无权限、无预算或无审计。所有外部副作用必须走 Tool Broker；Worker 不提供可绕过授权的任意执行入口。

### 5.2 Prepare 与 Approve

Prepare 只生成冻结事实，不启动搬运、创建影子表或提前发布；必要外部检查先作为独立受管操作执行，其结果和有效性纳入准备单。

Preparation 至少冻结：主体及归属、输入与版本指纹、EtlPlan/HOCON、连接资源标识、MetadataProfile/Schema、数据分级、质量规则、指标口径与预算、影响范围、发布与回滚方案、SecretReference 版本、适用策略版本、ApprovalSlot 及有效期。默认有效期 24 小时，审批不续期。

具名 Checker 基于该准备单独立作出 ApprovalDecision。任一拒绝、缺失审批、申请人自批、槽位复用或审批主体不合格均不能 Commit。上述冻结事实漂移需重新 Prepare 与 Approve；源端普通业务数据新增/更新本身不算指纹漂移，Schema 变化或凭据版本变化则必须重新检查。

### 5.3 Commit、Capability 与异步投递

Commit 重新检查准备单有效期、指纹、当前策略、主体权限、审批事实及职责分离；过期、撤权、漂移或策略禁止时给出明确拒绝和重新准备原因。使用幂等键接受请求，不能因网络重试产生多个业务运行。

Capability 使用 Ed25519 签名，绑定工具、主体、环境、资源和制品指纹，有效期 5 分钟，仅消费一次。Replay Guard 消费、ExecutionRun 创建及 Outbox 写入在同一 PostgreSQL 事务原子提交，任一步失败全部回滚。

事务 Outbox 和 Celery 允许重复投递；重复消息必须关联原 ExecutionRun 与 ManagedCommand。Worker 核验受管命令、签名及绑定范围，不把重复消费命令当作重新消费 Capability 或重新建立运行。已在期限内被合法接受的异步运行，不因排队超过五分钟就改成可重复授权；运行权限也不能脱离被冻结范围。

每次定时运行都创建独立 Preparation 并逐次审批，到点仅生成待审批申请；首版不提供无限期、无人值守的周期授权。

## 6. 执行、异常与状态核对

Worker 仅按授权范围获取 SecretReference 对应凭据、物化临时执行配置、提交 SeaTunnel 作业并上报事实；临时敏感材料按受管生命周期清理，不进入下载制品、消息或日志。Worker 与引擎的作业关联须可持久核对，不能只保存内存中的响应。

引擎提交成功但响应丢失时先进入提交结果待确认，执行 Reconciliation；不能盲目重提或直接声称不存在原作业。终止请求不等于终止成功，发布请求不等于发布已完成。提交、停止或发布结果不明时，阻止重复执行、发布和不安全清理，核对实际状态后才允许后续操作。

超限由已批准 RuntimeSupervisionContract 驱动受管中断，不等待人为修改质量阈值放行。Operator 发起的其他操作遵守相应策略与批准要求。诊断优先引用真实错误、指标与运行事实，给出脱敏的可解释原因和建议；模型推测须区别于已验证事实。取消成功不表示引擎撤销已写入影子表的数据，也不保证立即停止所有在途写入。

## 7. 凭据、样本与错误数据

SecretProvider 默认实现受管加密存储，主密钥由部署环境注入并与数据库分开保存；主密钥缺失时相关服务明确拒绝启动，不生成替代密钥掩盖旧凭据不可恢复。提供可选 Vault KV v2 适配，并验证存取、权限拒绝和轮转。

只读 MetadataProfile 探查必须限定资源、采样和预算。普通页面仅显示脱敏样本与必要统计；模型、日志、审计事件、API 错误及生成制品不得泄露凭据或敏感业务原值。

ErrorRecord 对普通字段可保留原值，敏感字段默认仅保留脱敏摘要、定位信息和错误原因。首版不提供敏感原值解密查看功能；如后续确需保留，必须使用受管加密和独立授权，不能沿用普通错误表权限。有效/错误 sink 中的业务数据不自动变成可公开的诊断数据。

SourceParseFailure 与已解析行质量违规区分：损坏 CSV、解码失败或无法证明完整读取时整批失败、禁止发布和静默跳过；保存受管源文件/资源引用及脱敏诊断证据。不承诺所有损坏 CSV 都能逐条分流，也不以 SQL 转换后的计数推导原始解析失败的总量。

## 8. 质量与运行监督

### 8.1 判定及计数

清洗转换和校验分开表达。已解析记录通过全部适用必需规则才可进入有效结果；任一必需规则失败生成一个 ErrorRecord，可包含多个 ErrorCode，但拒绝数只计一次。正常和错误路由应互斥、覆盖并明确 NULL 处理。

QualityReport 须分别记录源端读取行数、成功解析记录数、去重/关联后的质量判定记录数、通过全部必需规则的有效记录数、拒绝记录数、各规则命中/失败次数、最终实际写入行数和错误码分布，并记录必要的去重/合并及宽表转换计数和对账状态。每项保留数据集与处理阶段标识。规则次数和错误码数量不能当作通过/拒绝记录数；原始输入、增量行数、连接后的输出、历史完整快照行数不能互相替代。

Preparation 冻结：各计数的记录单元和阶段、重复/重试计数办法、拒绝率分母、放大比的输入/输出边界，以及字节数的测量来源和口径。拒绝率定义为被拒绝记录数除以已判定记录数；零分母显示暂无数据。放大比与写入字节口径在相关执行模式下必须可复核，不把估算字节声称为实测，也不把 sink 字节等同源库扫描或网络计费字节。

仅在同一冻结质量判定阶段、使用同一记录单元且完成重试去重后，要求“已判定记录数 = 有效记录数 + 拒绝记录数”。不能默认“源端读取行数 = ShadowTable 行数 + ErrorRecord 数”；连接、去重、历史保留和重试另作明确对账。输出放大比的分母阶段也必须冻结并实测。指标缺失、计数矛盾、错误分支失败或不完整读取不能显示为质量通过。

### 8.2 默认阈值与终止行为

| RuntimeSupervisionContract 项 | 默认值 |
| --- | ---: |
| 最大读取行数 | 100,000 行 |
| 最大写入字节数 | 256 MiB |
| 最大执行时长 | 600 秒 |
| 最大输出放大比 | 2 倍 |
| 最大拒绝率 | 20% |
| 监督间隔 | 约 2 秒，可配置 |
| 运行中拒绝比例检查最小已判定量 | 100 条 |

阈值变化进入版本/准备单并重新审批。运行中累计已判定至少 100 条后启用比例超限中断，结束时无论多少条都检查最终拒绝率；行数、字节、时长等不受最小样本量豁免。

发现超限立即请求取消、阻止发布并持续确认终态，记录阈值、检测时刻、取消请求与确认时刻、最终观测值及可解释原因。采集、轮询、网络与在途批次造成的超调允许存在，不承诺绝对资源上限。必要指标不可用须明确停止或阻断安全推进，不能按零消耗放行；可靠字节指标未验证时，相应预算验收未完成。

### 8.3 独立发布否决

即使 SeaTunnel 显示成功，仍需 QualityReport 完整、计数可核对、最终拒绝率达标、影子结构正确、运行预算符合已确认处置规则且无待确认状态，才能发布。默认空输入不得覆盖正式表；业务确需空表发布时，须显式写入计划并随版本审批。两个 sink 不默认具有跨表原子性，错误表成功不能掩盖有效分支失败，反之亦然。

## 9. 当前维度、水位、发布及恢复

订单为事实，用户为当前维度；暂不按订单发生时刻还原用户历史版本。订单增量采用更新时间加主键稳定排序、可配置重叠回看及主键合并；用户维度变更必须刷新受影响的历史订单。演示使用受控数据批次，覆盖同时间戳、重复运行及维度更新，不承诺跨源事务快照或无限迟到修改。

Watermark 只能在成功发布并确认对应控制事实后推进。失败和待确认运行不能提前推进；重跑验证不重复入库、不遗漏该边界内记录。

ManagedTarget 由平台独占写入、结构修改及发布，外部应用只读。同一实际数据库/表的完整影子构建到发布阶段串行，跨 Pipeline 也不能并发覆盖。外部 Schema 变化触发停止与重新检查。

ShadowTable 必须包含完整待发布结果，历史需保留的数据和本批变更均在其中；禁止仅用本批增量替换正式表。Doris 单条 `REPLACE WITH TABLE ... PROPERTIES('swap'='true')` 原子交换两个 OLAP 表：正式表获得新数据，交换后的另一张表保留原正式数据。平台自行验证 Schema 与对象身份，不把单次交换扩展为多个业务表、ETL 全程或 PostgreSQL 状态的原子事务。

PublicationRollback 仅恢复最近一次成功发布前保留的完整快照，默认保留七天；需双审批，并恢复该快照对应的控制状态和 Watermark。旧表删除、修改、过期或身份不明时拒绝回退，不自动合并发布后的外部写入。PrepublicationCleanup 仅在确认执行已停止后清理本次未发布结果，不可作为恢复旧正式版本的替代。

Doris 交换与控制面落库间故障进入 Reconciliation，核对实际表与 PublishedSnapshot 归属后恢复唯一可信状态；核对完成前禁止继续同目标运行、重复交换或误删旧数据。

## 10. 审计与可验证证据

EvidenceEvent 至少记录时间、主体、归属、操作类型、关联版本/准备单/运行、制品哈希、序号、事件哈希和前序哈希。关键链路形成哈希链与 Ed25519 签名 EvidenceCheckpoint；提供完整导出和独立离线校验入口，区别于普通调试日志。

验收实际修改、删除和重排事件，并验证签名检查点。识别完整尾部截断依赖此前由独立持有者在外部保存的检查点；只有剩余链条自洽不足以证明没有尾部删除。首版人工导出与外部保存即可，不要求第三方存证服务。审计报告准确表述为受信边界内可检测篡改，不作绝对不可篡改保证。

## 11. Benchmark、演示数据与结果报告

BenchmarkCase 具备稳定标识、版本、输入、预期及判定标准；EvaluationReport 固定测试集、策略、制品及 Provider/模型版本与真实运行条件，保留逐例结果、失败原因和证据引用。

| 层级 | 验证内容 | 不能替代的证据 |
| --- | --- | --- |
| L0 静态注入 | 提示注入、禁用工具、制品/指纹篡改、越权、语法与规则门禁 | 不能证明真实搬运、真实模型或引擎终止 |
| L1 模拟故障 | 重复消息、Outbox 故障、Worker 中断、提交超时、状态不明、审批失效、发布过程故障 | 不能以模拟结果宣称真实引擎接口或 Doris 兼容 |
| L2 真实链路 | 真实模型、真实数据库/CSV、SeaTunnel 执行、质量分流、预算、Swap 与恢复 | 缺模型或容器条件时必须标未执行/未通过，不能用确定性 Provider 替代 |

生成集合至少 20 例；最多两次自动修复后的端到端正确率目标 90%，同时检查门禁、字段映射及业务语义。自然语言初次通过与修复后通过分开报告，真实模型分数不得混入演示 Provider。安全硬门槛用例必须 100% 通过，覆盖自批、槽位复用、跨归属访问、令牌重放、指纹漂移和重复投递；P0/P1 拦截率分别说明集合、分母、漏拦截、误拦截与失败明细，不能以总平均值掩盖硬门槛失败。

演示基准约 1,000 条订单、100 条用户数据；正常批混入约 5% 异常订单，故障批约 30%，拒绝阈值为 20%。至少完成：

1. 真实模型生成与澄清恢复、门禁、独立双审批、实际运行、有效/错误分流、质量通过和 Swap 发布。
2. 超限运行、取消并确认终止、诊断、发布阻断、PrepublicationCleanup，证明正式表未被污染。
3. 另行验证 PublicationRollback，证明恢复上一快照及 Watermark，不能用第 2 项代替。

报告给出实际机器/容器资源、依赖版本、运行耗时和吞吐，不由小数据成功推断海量性能；复位与重复运行应得到可核对的相同业务结果。
